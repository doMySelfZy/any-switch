# 读取并纳管各客户端已有的 MCP 配置

## 背景

用户在使用本工具前，很可能已经在各 Agent 里手工配过 MCP（实测本机 Codex 就有 5 个：`ssh`/`context7`/`exa`/`tavily`/`sequential-thinking`）。当前实现只把自己数据库里的记录当作唯一来源，导致这些已有配置：

- 在界面里完全看不见；
- 不参与跨设备同步；
- 无法复用到其它客户端（想从 Codex 挪到 Claude Code 只能手抄）。

**已核实：现有实现不会破坏用户已有配置。** 合并逻辑只清理 `xiaobai_` 前缀的条目
（`adapters/mcp.rs` 的 `map.retain(|key, _| !key.starts_with(MANAGED_PREFIX) || ...)`），
`restore_official` 也只删 `env`/`model`/`effortLevel`/`apiKeyHelper`，从不触碰 `mcpServers`。
用用户真实配置推演确认：应用一个托管条目后，现有 5 个条目全部保留，含
`[mcp_servers.<name>.env]` 嵌套子表。所以本任务补的是**可发现性与可复用性**，不是修数据丢失。

## 核心设计问题：纳管后不能出现重复条目

若用户在 Codex 里已有 `exa`，我们纳管后又把托管条目写成 `xiaobai_exa`，Codex 会同时加载两个
同名服务，等于跑两遍。因此纳管必须能识别「客户端里那条未托管的、等价的条目」，并在应用时
用托管条目**替换**它而不是并存。

采用**快照校验 + 安全接管**：

1. 纳管时读取该条目的完整内容，存下内容指纹（不含明文密钥的哈希）。
2. 应用时，若目标客户端存在同名未托管条目且**指纹仍与纳管时一致** → 删除它、写入 `xiaobai_<name>`（净效果仍是 1 条）。
3. 若指纹已变（用户事后改过）→ 不删除，该目标报明确错误让用户决定，绝不覆盖用户的新改动。
4. 写前照既有约定备份 + 原子替换。

## 需求

### 扫描与展示
1. 新增扫描命令：读取四个客户端当前生效的 MCP 配置，返回条目清单。
   - Claude Code：`~/.claude.json` 顶层 `mcpServers`
   - Codex：`~/.codex/config.toml` 的 `[mcp_servers.*]`（须支持 `[mcp_servers.<name>.env]` 嵌套子表）
   - Pi：`<pi agent dir>/mcp.json`
   - Prime：`<prime agent dir>/settings.json`
2. 扫描结果区分三类，界面明确标识：
   - **我们托管的**（`xiaobai_` 前缀）
   - **用户自己的**（可纳管）
   - **已纳管**（在库里有对应记录，避免重复导入）
3. 扫描**只读**，不修改任何文件；**不得把明文密钥值返回给前端**——列表只展示条目名、传输方式、依赖的密钥**键名**（如「需要 `EXA_API_KEY`」），不展示值。

### 纳管
4. 单个纳管：把某客户端的某条目完整导入数据库，`env`/`headers` 走既有加密存储；记录来源客户端。
5. 批量纳管：一键纳管扫描到的全部用户条目。
6. 纳管是**非破坏性**的：不修改来源客户端文件（接管只发生在后续「应用」时，且有指纹校验）。
7. 纳管时按现有规则归一化名称（`[A-Za-z0-9_-]` 已合法则保持不变），重名报错清晰。

### 复用
8. 纳管后的条目与手动添加的完全等价：可选目标、可编辑、参与同步、可应用到任意客户端。

## 验收标准
- [ ] 扫描能列出四个客户端中用户已有的 MCP，含 Codex 的嵌套 `.env` 子表形状。
- [ ] 扫描结果**不含**任何明文密钥值（有测试断言返回值里不出现凭据内容）。
- [ ] 纳管后条目出现在列表中，`env`/`headers` 在库里加密存储（数据库内为密文）。
- [ ] 应用时，来源客户端里那条等价条目被替换为托管条目，**最终只有一条**，客户端不会重复加载。
- [ ] 条目在纳管后被用户改动过 → 应用不删除它，返回明确错误，原文件保持。
- [ ] 用户未纳管的条目在任何操作后都原样保留（含嵌套子表与无关配置段）。
- [ ] 纳管后可应用到其它客户端，实现跨客户端复用。
- [ ] 既有 MCP 行为、`xiaobai_` 托管约定、同步协议不变；不新增 schema 变更（复用现有表，或仅加来源标记列）。
- [ ] `cargo test`、`pnpm typecheck`、`pnpm test:run` 全绿。

## 明确不做
- 不自动纳管（必须用户确认，因为要把明文密钥搬进我们的库）。
- 不自动删除或改写用户未纳管的条目。
- 不做「双向持续同步」——不监听客户端文件变化反向更新数据库；纳管是一次性动作。
- 不接入第三方仓库（本任务与已完成的官方仓库搜索安装互不影响）。

## 约束
- 源码、示例、测试中不得出现可用凭据字面量；测试夹具一律用明显占位串。
- 读取到的密钥值不得写日志、不得回传前端、不得出现在错误信息里。
