# 站点列表侧栏加宽以完整显示三窗口额度摘要

## Goal

左侧站点列表侧栏加宽，使 OpenCode 三个用量窗口（5h / 周 / 月）的剩余百分比摘要在列表里完整显示，不再截断；右侧详情面板保持可用。

## 背景（2026-09-13 实测事实，勿再重复验证）

- 列表摘要的**三窗口展示代码已存在**（提交 `f6882d4`，`src/components/sites/SiteListItem.tsx`）：格式如 `5h 96% 周 76% 月 47%`，短标签来自 i18n（zh：`5h`/`周`/`月`；en：`5h`/`W`/`M`）。
- **用户已安装的版本不含该提交**（安装包由 `9218d45` 构建于 17:41，`f6882d4` 提交于 20:37）——所以现状截图里只有一个数值。本任务完成后必须重新打包安装。
- 当前侧栏 `w-64` = **256px**，列表项文字区（摘要容器）实测可用宽度 **137px**。
- 实测最坏情况：三个窗口均为三位数（`100%`，即刚重置未使用）时**需要 152px** → 当前必然出现 `text-overflow: ellipsis` 截断。
- 逐档实测（改侧栏宽度 → 量可用宽度）：256px→137、272px→153、**288px→169**、304px→185、320px→201。
- 结论：**`w-72` = 288px** 是最小安全值（余量 17px）。加载骨架（`SitesPage.tsx:372`）与实际布局（`SitesPage.tsx:414`）必须同步。
- 窗口尺寸：默认 1100×720，`minWidth` 900。w-72 下详情面板宽 812px（默认窗口）/ 612px（最小窗口）。
- 侧栏宽度无任何测试锁定（`grep -rn "w-64" src/ --include="*.test.*"` 无命中）。
- `w-64` 仅出现在 `src/pages/SitesPage.tsx` 两处，其他页面/组件不受影响。

## Requirements

1. `src/pages/SitesPage.tsx` 的两处侧栏（主布局与加载骨架）由 `w-64` 改为 `w-72`，两处保持一致。
2. 不改动摘要的字号、间距、颜色、文案与窗口标签；本任务只改容器宽度。
3. 默认窗口（1100px）与最小窗口（900px）下，右侧详情面板不得出现横向溢出或元素重叠。
4. 不改动其他页面/组件的宽度，不引入响应式折叠、可拖拽分隔条等新交互。
5. 不改 i18n、不改 Rust、不新增依赖。

## Acceptance Criteria

- [ ] 浏览器实测：三窗口均显示 `100%` 时，三个数值全部完整可见（无省略号截断），侧栏宽度 288px。
- [ ] 默认窗口（1100px）与最小窗口（900px）下详情面板 `scrollWidth <= clientWidth`（无横向溢出）。
- [ ] 加载骨架与主布局侧栏宽度一致（均为 `w-72`）。
- [ ] `pnpm typecheck` 通过；`pnpm test:run` 通过（仅允许本机预存在失败：`generateUpdaterManifest.test.ts`、`validateUpdaterSigningSecret.test.ts` 的 SyntaxError）。
- [ ] 重新打包安装后，在已安装应用里确认列表显示三窗口且不截断。

## 边界（不做）

- 不做响应式断点折叠、不做可拖拽调整宽度、不做列布局重构。
- 不改变额度语义（仍为「剩余」口径）。
- 不修改 `SiteListItem` 内部渲染逻辑（除容器宽度外零改动）。

## Notes

- 视觉验收必须用真实渲染测量（`getBoundingClientRect` / `scrollWidth`），不能只看代码。
