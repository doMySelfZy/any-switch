# 本地代理：按站点改写并转发 API 请求

## 目标

在 XiaoBaiSwitch Plus 内启动一个仅监听回环地址的 HTTP 代理。用户开启"接管"后，Claude Code / Codex / Pi / Prime 的 Base URL 指向本机代理，代理按站点注入或覆盖请求头（例如 OpenCode Go 强制的 `x-opencode-session`、客户端身份头），再把请求原样转发到站点真实上游。目标是让"渠道只接受特定客户端身份/特定请求头"的场景不再需要手工改客户端配置。

## 背景与缺口

- 现有链路只做静态配置写入：`SiteRow.base_url` → `normalize_base_url` → 各适配器写入目标 CLI。请求头没有任何调整能力。
- 部分渠道（OpenCode Go/Zen 等）在网关侧校验客户端身份与请求头，除请求头外还可能拦 UA；直接在客户端填上游 Base URL 会被拒。
- 站点编辑没有"自定义请求头"字段，数据库也没有对应存储。

## 需求

1. 代理服务：可启停；默认监听 `127.0.0.1:18087`（端口可配置）；仅允许回环地址，不暴露局域网。
2. 路径携带安装级随机 token（`/{token}/{target}/…`）：token 不匹配返回 404，避免本机其他程序误用/盗用站点密钥。
3. 目标路由：`claude_code` / `codex` / `pi` / `prime` 四目标各自可从"接管集合"里独立开关。接管开启时，该目标写入客户端的 Base URL 指向代理；关闭时恢复真实上游。
4. 上游解析：按目标的 target_binding → site → 该目标使用的真实上游 Base URL（与直连模式同一套 normalize 结果），请求路径为"客户端请求路径减去代理前缀后的剩余部分"，拼接规则与直连完全一致（四目标 × 两种协议都要对齐）。
5. 请求头改写：站点级有序请求头列表（name / value / enabled）；支持占位符 `${API_KEY}`（站点当前激活密钥，仅内存中替换）、`${SESSION}`（按站点稳定派生，跨重启不变）、`${UUID}`（每请求新生成）。客户端原始请求头默认全部透传，改写只做"新增/覆盖"。
6. 请求与响应全流式透传：支持 SSE，不缓冲整包；转发 `content-encoding`，不改动压缩语义。
7. 可观测：运行状态（监听地址、运行时长、总/成功/失败请求数、最近错误）+ 最近请求日志（时间、目标、路径、状态码、耗时、错误），日志不记录任何请求头或请求体，路径中的 token 必须脱敏。
8. 站点"高级配置"新增请求头编辑（JSON 文本域，与 MCP 表单同款校验），密钥类值仍可按需解密查看，列表不返回明文。
9. 退出安全：应用退出时若接管仍开启，尽力把已接管目标改回真实上游后再退出，避免"关掉应用 → CLI 全部不可用"。
10. 应用启动时若此前代理开关为开，则自动启动代理（与应用同生命周期）。

## 约束

- 不得改变既有数据/协议红线：`xiaobai_` 命名空间、备份前缀、WebDAV manifest 与远端目录名、`FINGERPRINT_TABLES` 语义均不动；本次只新增 `sites` 列并让新设置项进入既有 settings。
- 请求头值解密走现有 `Crypto`；密文只入 `sites.proxy_headers_encrypted`，明文不出命令边界（除按需查询命令）。
- 上游只来自数据库中的站点配置，绝不接受请求侧指定的任意 URL；仅允许 http/https。
- 不引入"请求体改写"能力，避免与流式协议语义脱节。
- 新增依赖只用本地 cargo 缓存已有的 hyper 1.x / hyper-util / http-body-util / http / bytes（均为 reqwest 传递依赖，无需联网下载）。

## 验收标准（已核对）

- [x] 代理启停可用；启动失败（端口占用等）返回结构化 `proxy_bind_failed`，UI 有提示；仅回环监听（`routing::LISTEN_HOST`）。
- [x] 路径口令不对/缺失返回 404，且日志中口令被剥离（`sanitize_log_path`，有单测）。
- [x] 四目标接管开关：开启后目标配置写入 `<proxy>/<token>/<target>`，关闭/停止代理由既有 rewrite 链路恢复真实上游；未接管的目标保持直连。
- [x] 站点自定义请求头在转发时生效；三个占位符替换正确、`${SESSION}` 按站点稳定；非法名/值与受保护头在**保存层与转发层**都被拒（两层各有单测）。
- [x] 直连与走代理的上游 URL 一致（`routing.rs` 路由表测试覆盖 4 目标 × 2 协议 × base 带/不带 `/v1`）。
- [x] SSE 逐块透传（集成测试经真实监听端口 + mock 上游，断言块顺序与内容）；非流式响应体一致。
- [x] 请求日志含状态码与耗时，不含任何请求头/请求体；200 条上限、环形淘汰（有单测）。
- [x] 应用退出时接管目标恢复直连并收掉运行意图（失败只记日志，不阻塞退出）；停止代理同样恢复直连。
- [x] 迁移：既有库升级后拿到两列、新库直接建全（各有回归测试）；旧备份/WebDAV 同步协议未改动。
- [x] `cargo test` 491 passed、`pnpm typecheck` 通过、`vitest` 347 passed（2 个 updater 脚本用例为本机既有失败，与本次无关）。

## 评审后补充的关键决策

- **路径口令存设备本地文件**（`~/.xiaobai-switch/local-proxy-token`）而不是 settings：settings 参与 WebDAV 同步，同步到别的机器后本机监听口令会与 CLI 配置里的口令不一致，表现为全部 404。
- **停止代理时恢复直连**：否则客户端配置仍指向本机端口而监听已关，四个 CLI 全部连接失败且界面无提示。
- **改端口顺带重启监听并重写接管地址**：否则重启后客户端仍指向旧端口。

## 明确不做

- 不做 Anthropic ⇄ OpenAI 协议转换（CC Switch 的能力，本次不引入）。
- 不做故障转移/熔断/自动换站。
- 不做请求体改写、响应体改写、模型名映射。
- 不做局域网/公网暴露与 TLS 终止。
- 不代理 MCP、技能或其他非模型 API 流量（只改写四个目标的模型 API Base URL）。
