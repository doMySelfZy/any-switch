# Master Implementation Plan
> Generated by Trellis — Outcome-Driven Development
> 功能目标：把「60 分钟定时备份 + 手动 WebDAV 恢复」升级为真正的多机配置同步

## Project Summary
XiaoBaiSwitch Plus 是管理多目标 AI CLI 配置（站点 / API Key / 目标预设 / Apply）的桌面工具。本次改进让它通过同一个 WebDAV 账户在 N 台机器之间保持**一份数据、处处一致**：配置改动即自动上传，换机器打开即自动拉取最新，全程无需人工备份或恢复。

## Phase A — Foundation（同步基础设施）

**Phase A 交付：**
- **远端版本指针**：WebDAV 上维护 `manifest.json`（单调递增 revision + 产生设备名 + 时间戳 + 数据包文件名 + SHA-256），是"谁更新"的唯一判据。
- **数据包格式**：复用现有备份 bundle（zip，内含 SQLite 数据 + `master.key` + manifest 元信息，带 sha256 校验）——换机解密问题因此天然解决。
- **本地同步账本**：新增 revision 记录（最近上传/最近应用的远端版本），存于应用数据库。
- **同步引擎**（Rust）：`sync_now(reason)` 统一入口，覆盖上传/下载两条路径；应用远端数据前**强制先生成本地快照**（复用 `create_local_backup`）。
- **回滚能力**：快照列表 + 一键回滚（复用现有 `restore_backup_in` / `validate_and_extract_bundle`）。

**Phase A 验证里程碑：**
_"手动触发一次同步后，WebDAV 上出现 manifest + 数据包；再触发一次，revision 前移且本地可回滚到同步前。"_

---

## Phase B — 变更即同步（两个可并行的 Outcome）

**Outcomes:**
- [ ] **配置变更自动上传同步** — 数据写操作后发 dirty 事件，防抖合并（秒级）后打包上传并前移 manifest；失败进入待重试队列并在 UI 提示，绝不静默丢包。
- [ ] **切机自动拉取最新数据** — 应用启动 / 窗口聚焦时读取 manifest，远端比本地新则自动下载 → 校验 → 快照 → 原子替换本地数据并刷新界面。

**说明：**
- 现有 60 分钟定时器降级为**兜底**（间隔档位保留 15/30/60/120/360/720/1440，可关闭），主触发改为"变更即推 + 打开即拉"。
- Apply 写出的目标 CLI 配置（`~/.claude` 等）**不参与同步**——每台机器各自 Apply，同步的是 XiaoBaiSwitch Plus 自己的数据。

**Phase B 验证里程碑：**
_"A 机改一个站点，B 机打开 XiaoBaiSwitch Plus 直接看到最新数据，全程零手动操作。"_

---

## Phase C — 同步安全与 UX 完善

**Outcomes:**
- [ ] **同步不丢数据** — 冲突（本地有未上传变更且远端也更新）时按设备名 + 时间戳保留双方版本供追溯，用户显式确认后才覆盖；任何时刻可从快照回滚。

**关键交互：**
- 设置页新增"同步状态"：最近同步时间 / 结果 / 待重试 / 冲突入口。
- 高危动作二重确认：应用远端数据、回滚快照前展示影响范围。

**Phase C 验证里程碑：**
_"模拟双机同时修改、断网、远端坏包三个场景，本地数据在任何情况下无损、可回滚、可追溯。"_

---

## Build Order — Why This Sequence
先有安全网（快照 + 回滚），才敢自动覆盖本地数据；先建立远端版本指针与数据包格式（上传路径），拉取路径才有东西可判断；冲突处理依赖前两者，所以放最后。UI 状态区随各阶段同步补充，不做单独阶段。

---

## Integration Checkpoints

**End of Phase A:**
- [ ] WebDAV 上出现 `manifest.json` + 数据包，revision 可递增，本地快照可回滚。

**End of Phase B:**
- [ ] 双机端到端：A 改 → B 开即最新；断网补传成功。

**End of Phase C:**
- [ ] 三个故障场景（双机同时改 / 断网 / 坏包）全部数据无损。

---

## 关键设计决策（记录备查）
1. **复用备份 bundle 格式**（含 master.key）→ 不新造序列化，换机解密零成本。
2. **manifest 单调 revision 为唯一新旧判据**；WebDAV 无原子锁，并发写靠"revision + 设备名 + 快照兜底"保证不丢数据，不追求分布式一致性。
3. **数据范围**：`~/.xiaobai-switch/` 内的站点/密钥/设置参与同步；各目标 CLI 配置目录不参与。
4. **触发模型**：变更即推（防抖秒级）+ 打开即拉（启动/聚焦）+ 定时兜底（可关）。
